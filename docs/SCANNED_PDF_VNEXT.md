# 扫描型 PDF VNext

## 目标

提高图片型报价单、发票和材料表的翻译可读性，同时保持图片、条码、印章、金额与表格版式不被覆盖。此版本不引入大型 AI 模型；先在现有 Poppler、Tesseract、PDF.js 与布局引擎上实现几何规则。

## 处理流程

`扫描页 → 几何提取 → 区域构建 → 区域内 OCR → 过滤 → 翻译 → 单元格拟合 → 碰撞校验 → 预览/PDF 导出`

每个 OCR 翻译单元至少保存 `sourceText`、`sourceBBox`、`writableRegion`、`layoutType`、`obstacles`、`confidence` 和最终 `translationBBox`。预览和 PDF 导出只能读取同一份最终布局结果，不得各自重新换行或缩放。

## 五项范围与验收

### 1. OCR 分区

- 从 PDF 矢量线、OCR 坐标和页面图像几何中识别表格单元格、普通文字区、图片、条码、印章和图形。
- 有可靠边框时，表格线优先于文字对齐；无可靠边框时，以图片禁区和空白走廊切分区域。
- OCR 文字只能归属一个可写区域，不能跨列、跨单元格或跨禁区。

验收：扫描报价单的型号、描述、数量、单价、金额列分别在原列内翻译，描述不得覆盖产品图。

### 2. OCR 结果过滤

- 丢弃低置信度杂点和低于最小可读尺寸的文本。
- 条码区域永不进入 OCR 翻译。
- 纯数字、金额、日期、货币、常见型号和料号默认保留原文；需翻译时由显式规则放行。

验收：条码没有文字覆盖；数量、金额、型号与原文完全一致；调试覆盖层能显示被过滤的原因。

### 3. 译文排版

- 在 `writableRegion` 内先换行，再压缩行距，再缩小字号；字号不得小于原字号的 70%。
- 不能放入时不扩大表格行高，也不推移下方内容；保留原文并产生带页码和区域标识的问题记录。
- 最终逐行检查译文边界。

验收：译文不越出单元格、不重叠相邻内容；失败区域有可理解提示而非脏画面。

### 4. 扫描页背景遮罩

- 图片型 PDF 的原文属于底图像素，不能使用 clean-background 文本操作删除。
- 仅对已确认的文本区域绘制局部白底遮罩，并在四周增加 2–4 pt 安全边距。
- 遮罩与图片、条码、印章相交时，优先缩小区域或放弃翻译，不得覆盖障碍物。

验收：预览与导出中原文和译文不重叠，Logo、产品图片、条码、印章完整保留。

### 5. 共享布局与碰撞验证

- `text-fitter` 输出单一布局结果，React 预览和 PDF 导出复用该结果。
- `collision-validator` 确认每个最终译文框位于可写区域，且不与障碍物相交。
- 验证失败按顺序回退：更小区域 → 更小字号 → 保留原文并报告问题。

验收：同一页预览与导出的翻译位置、换行和字号一致；测试覆盖型号+图片+描述、合并单元格、缺失单元格、无边框图片表格、长译文和图片碰撞。

## 非目标

- 本版本不把主程序从 Rust/TypeScript 改写为 Python。
- PaddleOCR、PP-StructureV3、Docling 等大型模型仅作为未来可选下载的高级 OCR 后备，不阻塞本版本。
